# Architecture

This document explains how the Vellira monorepo is organized and where each
kind of code belongs.

## Goals

Vellira is built around a few architectural goals:

- one design language shared across Web and React Native;
- renderer-specific implementation details kept inside renderer packages;
- stable public APIs exposed only from package roots;
- generated artifacts kept reproducible and out of source ownership;
- tests and documentation close enough to implementation to stay current.

## Layers

```text
Primitive tokens
        ↓
Semantic tokens
        ↓
Component tokens
        ↓
Shared contracts and behavior
        ↓
Renderer packages
        ↓
Apps, docs, Storybook, playgrounds
```

Each layer should depend only on the layers above it in the diagram.

## Packages

| Package                    | Role                                      |
| -------------------------- | ----------------------------------------- |
| `@vellira-ui/tokens`       | Primitive, semantic, component tokens     |
| `@vellira-ui/types`        | Renderer-neutral TypeScript contracts     |
| `@vellira-ui/core`         | Shared hooks and interaction logic        |
| `@vellira-ui/icons`        | Cross-platform icon components            |
| `@vellira-ui/react`        | React DOM components and CSS modules      |
| `@vellira-ui/react-native` | React Native components and StyleSheet UI |
| `@vellira-ui/assets`       | Fonts and static shared assets            |

## Applications

| App                      | Role                                    |
| ------------------------ | --------------------------------------- |
| `apps/docs`              | VitePress documentation site            |
| `apps/react-storybook`   | Web Storybook and visual review surface |
| `apps/native-storybook`  | Expo React Native Storybook             |
| `apps/react-playground`  | Web playground                          |
| `apps/native-playground` | Expo playground                         |

Apps may depend on packages. Packages must not depend on apps.

## Dependency Direction

Rules:

- `tokens` must not import renderer packages.
- `types` must not import runtime code.
- `core` must not import web or native code.
- `react` must not import `react-native`.
- `react-native` must not import `react`.
- `icons` may expose web and native entry points, but consumers choose the
  renderer through package exports.
- docs, Storybook, and playground apps may compose public package APIs only.

## Component Ownership

Shared component shape belongs in `@vellira-ui/types`.

Renderer-specific props belong in the renderer package:

- web owns DOM props, `className`, browser events, CSS modules, ARIA attributes;
- native owns `style`, `textStyle`, `testID`, `accessibilityLabel`, `onPress`,
  and React Native primitives.

Component source stays next to its tests and stories:

```text
packages/react/src/primitives/Button/
├── Button.tsx
├── Button.module.scss
├── Button.stories.tsx
├── Button.test.tsx
├── types.ts
└── index.ts
```

React Native components use `*.styles.ts` instead of CSS modules.

## Token Ownership

Token source lives in `packages/tokens/src`.

Token layers:

- primitive colors in `primitives`;
- semantic groups in `light/semantic`, `dark/semantic`, `highContrast/semantic`;
- component groups in `light/components`, `dark/components`,
  `highContrast/components`;
- generated type and CSS variable metadata in `src/generated`.

Generated files must be updated with package scripts, not hand-edited.

## Public APIs

Public exports are intentional package contracts. Add or remove them only when
the change is deliberate and documented.

Use:

```bash
pnpm check:public-api
```

when changing package entry points.

## Build And Verification

Common local gates:

```bash
pnpm typecheck
pnpm test
pnpm docs:api:check
pnpm check:public-api
pnpm docs:build
```

Full CI:

```bash
pnpm ci
```

For focused iteration, run package-level commands:

```bash
pnpm --filter @vellira-ui/react test
pnpm --filter @vellira-ui/react-native typecheck
pnpm --filter @vellira-ui/tokens test
```

## Generated Artifacts

Generated artifacts include:

- package `dist/` folders;
- token type unions and CSS metadata;
- generated icon sources;
- API docs generated by `scripts/generate-api-docs.ts`.

Generated artifacts should be reproducible from scripts. If generated API docs
change, make sure the source API change is intentional.
