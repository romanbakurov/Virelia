# Theming

Vellira theming is token-driven. Components do not choose primitive palette
values directly; they consume semantic and component tokens from a theme object.

## Theme Layers

```text
colors
  ↓
semantic
  ↓
components
  ↓
renderer implementation
```

Use the lowest layer that matches the decision:

- primitive `colors` for token authoring only;
- `semantic` tokens for reusable UI meaning;
- `components` tokens for component-specific states;
- renderer styles consume semantic and component tokens.

## Available Themes

The token package provides:

- `lightTheme`;
- `darkTheme`;
- `highContrastTheme`;
- `theme` as the default light theme.

```ts
import { darkTheme, highContrastTheme, lightTheme } from '@vellira-ui/tokens';
```

## Web Theming

Web components use CSS variables generated by `@vellira-ui/tokens` and packaged
through `@vellira-ui/react/styles`.

Import styles once:

```tsx
import '@vellira-ui/react/styles';
```

Use `ThemeProvider` to select the component theme:

```tsx
import { ThemeProvider } from '@vellira-ui/react';

export function App() {
  return (
    <ThemeProvider defaultTheme='light'>
      <Routes />
    </ThemeProvider>
  );
}
```

Component styles should use CSS variables:

```scss
background: var(--surface-default);
color: var(--text-primary);
border-color: var(--border-default);
```

## Native Theming

Native components use theme objects directly.

```tsx
import { ThemeProvider } from '@vellira-ui/react-native';

export function App() {
  return (
    <ThemeProvider defaultTheme='light'>
      <Screen />
    </ThemeProvider>
  );
}
```

Native styles should read from `NativeTheme`:

```ts
backgroundColor: theme.components.input.default.bg;
borderColor: theme.components.input.default.border;
```

## Component Tokens

Component tokens describe stateful values.

Button example:

```ts
theme.components.button.primary.solid.default.bg;
theme.components.button.primary.solid.hover.bg;
theme.components.button.primary.solid.pressed.border;
theme.components.button.disabled.fg;
```

Input example:

```ts
theme.components.input.default.bg;
theme.components.input.focus.border;
theme.components.input.disabled.placeholder;
```

## Focus

Focus is semantic, not component-specific by default.

Use:

```ts
theme.semantic.focus.ring;
theme.semantic.focus.ringOffset;
```

Focus should add a ring or outline on top of the current state. It should not
replace hover or pressed background unless the design explicitly calls for it.

## Adding A Theme Token

1. Add or reuse a primitive color only inside `packages/tokens`.
2. Add semantic meaning when the value is reusable across components.
3. Add component tokens when the value is specific to a component state.
4. Update all themes: light, dark, and high contrast.
5. Regenerate token types.
6. Update docs and examples.
7. Run token tests.

Commands:

```bash
pnpm --filter @vellira-ui/tokens generate:types
pnpm --filter @vellira-ui/tokens test
```

## Rules

- Do not use primitive colors inside renderer components.
- Do not hardcode colors when a semantic or component token exists.
- Do not add one-off semantic tokens for a single component state; use component
  tokens instead.
- Keep token names role-based: `bg`, `fg`, `border`, `ring`, `placeholder`,
  `icon`.
- Keep state names predictable: `default`, `hover`, `pressed`, `focus`,
  `disabled`, `error`, `success`.
